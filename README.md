## 결과와 고찰

### 1. 이력(hysteresis)으로 인한 영점 틀어짐

**현상**: 같은 기준 자세 명령을 반복해도 로봇이 처음 기준 자세로 돌아오지 못하고, 관절 영점이 조금씩 어긋났습니다.

**원인 분석**
- 취미용 서보(MG90S)는 내부 기어의 **백래시**와 제어기의 **데드밴드**가 있어서, 같은 각도를 명령해도 어느 방향에서 접근했는지에 따라 실제 멈추는 각도가 달라집니다. 이게 이력 현상입니다.
- 서보 혼(horn)은 톱니 단위로만 끼울 수 있어서 조립할 때부터 관절마다 영점 오차가 남습니다.
- 프레임과 접착부가 하중을 받으면 조금씩 휘어서 오차가 더해집니다.
- 한 다리에 관절이 3개라 관절마다 생긴 작은 각도 오차가 다리 끝에서는 더 큰 위치 오차로 커집니다.

**개선 방향**
- 서보마다 영점 보정값(offset)을 측정해서 코드에 반영
- 목표 각도에 항상 같은 방향으로 접근하게 해서 백래시 영향 줄이기
- 위치 피드백이 있는 서보(예: 스마트 서보)로 바꿔 폐루프 제어

### 2. 특이점을 고려하지 않은 설계

**현상**: 영상처럼 다리가 특정 자세 근처에서 갑자기 튀거나 의도와 다른 방향으로 움직였습니다.

**원인 분석**
- 3자유도 다리에는 관절 각도를 조금만 바꿔도 다리 끝이 원하는 방향으로 움직이지 못하는 자세가 있는데, 이를 **특이점**이라고 합니다. 대표적으로 무릎(Femur–Tibia)이 완전히 펴지거나 접힌 자세(작업공간 경계), 그리고 다리 끝이 Coxa 회전축 위에 오는 자세입니다.
- 이 근처에서는 다리 끝을 조금만 움직이려 해도 관절 각도가 크게 바뀌어야 하고, 역기구학 해가 한 형태에서 다른 형태로 바뀌면서 관절이 튀는 동작이 나옵니다.
- 룩업 테이블 방식이라 이 문제가 더 크게 드러났습니다. 테이블은 일정 간격의 격자로 되어 있는데, 특이점 근처에서는 바로 옆 칸끼리도 관절 각도 차이가 크고, 해의 형태(무릎 위/아래)가 칸마다 바뀔 수 있습니다. 그래서 다리 끝이 한 칸만 이동해도 관절이 크게 튀었습니다.
- 설계할 때 다리 끝 궤적이 이런 자세를 피하도록 작업공간을 따지지 않아서 영상과 같은 움직임이 생겼다고 판단합니다.

**개선 방향**
- 다리 끝 궤적을 작업공간 안쪽으로 제한하고 무릎 각도에 여유(margin) 두기
- 역기구학 계산에서 해가 없는 입력(도달 불가 위치)을 검사하고, 한 가지 해 형태(예: 무릎 위쪽)로 고정
- 3자유도 다리는 역행렬 없이 삼각함수(atan2)와 코사인 법칙만으로 닫힌 형태의 해를 구할 수 있습니다. 룩업 테이블 대신 이 식을 쓰면 메모리를 아끼면서 격자 간격에 따른 오차와 튀는 현상도 줄일 수 있습니다
- 링크 길이와 관절 가동 범위를 먼저 시뮬레이션해서 궤적을 검증한 뒤 하드웨어에 적용

### 배운 점

- 하드웨어를 직접 만들면 시뮬레이션에서 보이지 않는 오차(백래시, 조립 오차, 프레임 변형)가 제어 결과를 크게 좌우한다는 것
- 기구 설계 단계에서 작업공간과 특이점을 먼저 따져야 한다는 것
